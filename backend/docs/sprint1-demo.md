## 3. 예외·경계 케이스 (팀 선택 3개 + 자동 테스트)

루브릭 2번(3점)은 "중복·경계값·잘못된 입력·권한 오류"를 봅니다. 네 유형을 모두 덮도록 골랐습니다.

| # | 유형 | 시나리오 | 기대 결과 | 자동 테스트 |
|---|---|---|---|---|
| 1 | **중복(동시성)** | 학생 10명이 같은 좌석·시간 동시 예약 | 1건만 성공, 9건 409, DB 예약 1건 | `pytest -m integration -v tests/integration/test_us05_concurrency.py` |
| 2 | **경계값** | 10~12시 예약 뒤 12~14시 예약 / 오늘+7일 허용, +8일 거부 / 정확히 4시간 허용, 5시간 거부 / 체크인 마감 10:14 취소 허용, 10:15 거부 | 경계 시각은 겹치지 않음, 기간 양 끝 포함 | `pytest -v tests/unit/test_booking_rules.py` + `pytest -v -k "adjacent or deadline or checkin_wait"` |
| 3 | **권한 오류** | 학생 B가 학생 A의 예약 취소 / 관리자가 학생 API 호출 | 403 NOT_OWNER / 403 FORBIDDEN_ROLE | `pytest -v -k "forbidden or admin_cannot"` |
| (예비) | 잘못된 입력 | 약한 비밀번호 4종, 잘못된 취소 사유 | 400 + 안내 | `pytest -v -k "weak_password or invalid_reason"` |

화면으로 보여줄 수 없는 AC 4개: `pytest -v -k "us03_ac3 or us09_ac2 or us09_ac3 or us02_ac2"`

동시성 통합 테스트는 `TEST_DATABASE_URL`이 필요합니다 (PowerShell):
`$env:TEST_DATABASE_URL="mysql+pymysql://lsrs:lsrs_pw@127.0.0.1:3306/lsrs_test?charset=utf8mb4"` → `pytest -v tests/integration/test_us05_concurrency.py`

데모 직전 한 번에 확인: `pytest -v` (단위 전체) → 통과 개수가 보이는 화면을 캡처해 두면 Q&A에서 바로 보여줄 수 있어요.

## 4. 코드 설명 준비 (개인 4점)

각자 **1~2분**, IDE에서 아래 순서로 말합니다.
1. 이 함수가 하는 일 (AC 한 줄)
2. **왜 이렇게 동작하는가** — 설계서 근거 (Core Flow, Business Rule, 명세서 FR)
3. 다른 방법을 안 쓴 이유 (대안 질문 대비)
4. **AI가 만든 부분 / 내가 직접 고치고 검증한 부분** — 커밋으로 보여주기

| 담당 | 열어둘 파일·함수 | 꼭 설명할 "왜" | 예상 질문 |
|---|---|---|---|
| 남준혁 (US-01·02·03) | `services/auth_service.py` `signup`, `login` / `core/deps.py` `get_current_user` | 비밀번호를 왜 BCrypt로? 토큰을 왜 HttpOnly 쿠키에? 로그아웃이 왜 즉시 무효인가(세션 DB 확인) | "JWT만으로는 로그아웃이 왜 안 되나요?" "6번째에 잠그는 근거는?" |

**AI 생성 vs 직접 수정 구분 표** (각자 작성 → 스프린트 로그①에도 그대로 사용)

| 파일·함수 | AI가 만든 것 | 내가 고치거나 검증한 것 | 근거(테스트·커밋) |
|---|---|---|---|
| 예) `reservation_repository._overlap` | 겹침 조건 초안 (`<=` 사용) | 경계 시각이 겹치는 버그 → `<`로 수정 | `test_us05_adjacent_slot_allowed`, 커밋 abc123 |
| | | | |

> 스켈레톤(구조·스텁·테스트 틀)은 AI가 만들었습니다. **함수 본문은 각자 직접 작성하고, `pending` 표시를 지운 테스트를 통과시키는 과정을 커밋으로 남기세요.** 그게 "직접 검증"의 증거가 됩니다.
