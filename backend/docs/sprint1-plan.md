## 3. AC 체크리스트 (Product Backlog 기준)

### US-01 회원가입·이메일 인증 (Must / 5) — 담당: ____
- [ ] AC1 유효 입력 → PENDING 생성 + 인증 코드(6자리) 메일 발송
- [ ] AC2 인증 완료 → ACTIVE + ROLE_STUDENT
- [ ] AC3 비밀번호 규칙 위반 → 거부 + 규칙 안내
- [ ] AC4 학번/이메일 중복 → 거부 + 안내

### US-02 로그인·로그아웃·역할 접근 제어 (Must / 5) — 담당: ____
- [ ] AC1 ACTIVE + 비밀번호 일치 → 유효 시간 있는 토큰 발급 (Access 1h / Refresh 7d)
- [ ] AC2 학생이 관리자 기능·타인 예약 접근 → 403
- [ ] AC3 PENDING 계정 로그인 → 이용 제한 + 이메일 인증 안내
- [ ] AC4 로그아웃 → 즉시 무효화 (세션 revoked)

### US-03 로그인 실패 잠금 (Should / 3) — 담당: ____
- [ ] AC1 5회 실패 상태에서 6번째 실패 → LOCKED (시간 제한 없음)
- [ ] AC2 LOCKED → 올바른 비밀번호여도 거부
- [ ] AC3 잠금 전 성공 → 실패 횟수 0 초기화

### US-04 좌석 현황 조회 (Must / 3, 기준 스토리) — 담당: ____
- [ ] AC1 그리드 + 4상태(예약 가능/사용 중/내 예약/예약됨), 500ms 이내
- [ ] AC2 날짜·시간대 변경 시 즉시 갱신
- [ ] AC3 과거·예약 가능 일수 초과 → 안내 메시지

### US-05 예약 생성 (Must / 8) — 담당: ____
- [ ] AC1 제한 아님 + 가용 좌석 + 유효 시간 → RESERVED 저장 + 완료 메시지
- [ ] AC2 동일 좌석·시간 동시 요청 → 1건만 성공(200), 나머지 409 + 안내
- [ ] AC3 같은 학생 같은 시간대 중복 → 거부
- [ ] AC4 이용 제한 학생 → 거부 + 해제일 안내

### US-06 내 예약 내역·필터 (Must / 3) — 담당: ____
- [ ] AC1 본인 전체 이력 최신순
- [ ] AC2 상태 필터
- [ ] AC3 이력 없음 → 오류 없이 안내 문구

### US-09 직접 취소 (Must / 3) — 담당: ____
- [ ] AC1 RESERVED 예약 + 사유 선택 → 취소, 좌석 즉시 가용
- [ ] AC2 노쇼 패널티 없음 (`penalty_applied=False`, `no_show_count` 불변)
- [ ] AC3 이미 체크인 완료·취소된 예약 → 취소 불가 안내 (409 `NOT_CANCELLABLE`)

## 4. 중간 데모 시나리오 (리허설용)

1. 신규 학생 가입 → 콘솔/메일의 6자리 코드로 인증 → 로그인
2. 날짜·시간 선택 → 좌석 그리드 4상태 확인
3. 좌석 예약 → "내 예약"으로 표시 확인
4. **동시성**: 학생 2명이 같은 좌석·시간 동시 예약 → 1건 200 / 1건 409 (통합 테스트 실행 화면으로 시연)
5. 내 예약 목록 필터 → 예약 취소(사유 선택) → 좌석이 다시 "예약 가능"
6. 예외: 비밀번호 6회 오류 잠금, 학생이 관리자 API 호출 시 403
7. 팀원별 코드 설명 (각자 2~3분: 핵심 함수 1개 + "왜 이렇게 했는가" + AI 수정 사례 1개)
